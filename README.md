# Мониторинг горячего и льготного питания

Веб-приложение для МКУ «Отдел образования администрации Зейского муниципального округа». Предназначено для ежедневного сбора и сводного мониторинга данных об организации горячего и льготного питания в подведомственных образовательных организациях.

Проект выполнен как учебный прототип: простой стек, минимум зависимостей, запуск одной командой.

## Возможности

- Личный кабинет образовательной организации с авторизацией по логину и паролю.
- Ежедневная форма из трёх числовых показателей: начальные классы с горячим питанием, льготники, плательщики.
- Блокировка повторной отправки отчёта за текущие сутки на уровне интерфейса и базы данных.
- Панель отдела образования без пароля (по требованию к демонстрационному прототипу).
- Сводная таблица за текущую дату по всем учреждениям района.
- Подсветка бледно-красным цветом всей строки организации, не представившей отчёт.
- Строка итогов по району, суммы рассчитываются на JavaScript.
- Строгий государственный дизайн: белый фон, тёмно-синяя шапка, прямые углы, крупная типографика без засечек.
- Адаптивная вёрстка для планшетов и телефонов.

## Соглашение о вёрстке

Разметка и стили написаны по методологии **БЭМ**. Используется нотация `block__element_modifier`:

- блок — самостоятельный компонент: `header`, `form`, `report-table`, `button`;
- элемент — часть блока: `header__title`, `form__input`, `report-table__cell`;
- модификатор — вариант блока или элемента: `button_view_primary`, `status_value_ok`, `report-table__row_state_missing`.

CSS содержит только селекторы классов БЭМ. Утилитарных классов, вложенных каскадов и стилизации по идентификаторам нет. JavaScript использует `id` только для доступа к элементам, а переключение состояний выполняет через классы БЭМ.

## Технологии

| Слой | Технология |
|---|---|
| Фронтенд | HTML5, CSS3, Vanilla JavaScript (без фреймворков) |
| Бэкенд | Node.js, Express 4 |
| База данных | SQLite через встроенный модуль `node:sqlite` |
| Сессии | `express-session` |
| Пароли | `scrypt` + случайная соль (`node:crypto`) |

> **Важно:** используется встроенный в Node.js модуль `node:sqlite`, поэтому не требуется устанавливать `better-sqlite3`, компиляторы C++ или Visual Studio Build Tools. Нужен только Node.js 24 или новее.

## Быстрый запуск

```bash
cd zeya-nutrition-monitoring
npm install
npm start
```

В Windows можно также дважды щёлкнуть файл `start.bat` — он сам установит зависимости (при первом запуске) и запустит сервер.

После запуска:

- личный кабинет организации — <http://localhost:3000>
- панель отдела образования — <http://localhost:3000/admin>

База данных создаётся автоматически при первом запуске в файле `data/nutrition.db` и заполняется пятью учреждениями.

Для разработки с автоматическим перезапуском:

```bash
npm run dev
```

Полностью пересоздать базу с тестовыми данными:

```bash
npm run db:reset
```

### Если команда `npm` не запускается в PowerShell

Windows может запретить выполнение файла `npm.ps1`. Используйте `npm.cmd`:

```powershell
npm.cmd install
npm.cmd start
```

Либо разрешите локальные скрипты для текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

После установки Node.js закройте и снова откройте терминал, чтобы обновился `PATH`.

| МАОУ Береговая СОШ | `beregovaya` | `school2026` |

## Сценарий демонстрации

1. Выполните `npm run db:reset`, затем `npm start` — база создаётся заново, отчётов за сегодня нет.
2. Откройте <http://localhost:3000/admin>: все пять организаций подсвечены бледно-красным, итоги равны нулю.
3. Во втором окне откройте <http://localhost:3000> и войдите, например, как `school1` / `school2026`.
4. Заполните три показателя и отправьте отчёт. Покажите, что форма заблокировалась, а повторная отправка недоступна.
5. Обновите страницу `/admin`: строка школы стала обычной, появились цифры, итоги пересчитались.
6. Войдите как другая школа (`school4`) и сдайте ещё один отчёт — итоги увеличатся, оставшиеся организации по-прежнему будут красными.
7. Для повторной демонстрации снова выполните `npm run db:reset`.

## Как пользоваться

### Представитель школы

1. Откройте <http://localhost:3000>.
2. Войдите под логином своего учреждения.
3. Заполните три поля за текущую дату.
4. Нажмите «Отправить отчёт за сегодня».
5. После успешной отправки появится подтверждение, а форма заблокируется до следующего дня. Повторная отправка за эту же дату невозможна.

Отчётная дата определяется на сервере по часовому поясу `Asia/Yakutsk` (Зейский муниципальный округ, UTC+9). Это исключает расхождение дат у пользователей с разными настройками компьютера.

### Специалист отдела образования

1. Откройте <http://localhost:3000/admin>.
2. Пароль не требуется — так задумано в демонстрационном прототипе.
3. В таблице всегда отображаются все учреждения из базы.
4. Если отчёт сдан, видны присланные цифры и статус «Сдан».
5. Если отчёт не сдан, вся строка подсвечена бледно-красным, в статусе — «Нет данных».
6. В нижней строке автоматически рассчитаны итоги по каждой колонке для всего района.

## База данных

Файл базы: `data/nutrition.db` (путь можно изменить переменной `DB_PATH`).

### Таблица `schools`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | Идентификатор учреждения |
| `name` | TEXT | Название учреждения |
| `login` | TEXT UNIQUE | Логин |
| `password` | TEXT | Хеш пароля в формате `scrypt$соль$хеш` |

### Таблица `reports`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | Идентификатор записи |
| `school_id` | INTEGER FK | Ссылка на учреждение |
| `report_date` | TEXT | Дата отчёта в формате `YYYY-MM-DD` |
| `primary_hot_meals` | INTEGER | Ученики начальных классов с горячим питанием |
| `beneficiaries` | INTEGER | Льготники |
| `paying` | INTEGER | Плательщики |

Ограничение `UNIQUE (school_id, report_date)` гарантирует, что одно учреждение не сможет отправить два отчёта за одну дату, даже при одновременных запросах.

### Первичное заполнение

Функция `initializeDatabase()` в `database.js` вызывается при старте сервера. Она создаёт таблицы и добавляет отсутствующие учреждения. Повторный запуск не создаёт дубликаты и не сбрасывает уже изменённые пароли.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `NODE_ENV` | не задано | `production` включает secure-cookie и HSTS |
| `SESSION_SECRET` | dev-значение | Секрет подписи сессионной cookie. Обязательно задать в production |
| `APP_TIMEZONE` | `Asia/Yakutsk` | Часовой пояс отчётной даты |
| `DB_PATH` | `data/nutrition.db` | Путь к файлу SQLite |

Пример запуска в production:

```bash
NODE_ENV=production SESSION_SECRET="длинная-случайная-строка" npm start
```

В Windows PowerShell:

```powershell
$env:NODE_ENV="production"
$env:SESSION_SECRET="длинная-случайная-строка"
npm start
```

## API

Все ответы — JSON. Для личного кабинета используется сессионная cookie `zeya.sid`.

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/api/auth/login` | публичный | Вход по логину и паролю |
| `POST` | `/api/auth/logout` | публичный | Выход, удаление сессии |
| `GET` | `/api/auth/me` | публичный | Проверка сессии, текущая дата и отчёт за сегодня |
| `POST` | `/api/reports` | только школа | Отправка отчёта за текущую дату |
| `GET` | `/api/admin/today` | публичный (по ТЗ) | Сводка по всем учреждениям за текущую дату |

Пример отправки отчёта:

```json
{
  "primaryHot": 120,
  "beneficiaries": 35,
  "paying": 85
}
```

Пример ответа сводки:

```json
{
  "date": "2026-11-05",
  "timezone": "Asia/Yakutsk",
  "schools": [
    {
      "id": 1,
      "name": "МБОУ Сосновоборская СОШ",
      "report": {
        "primaryHot": 120,
        "beneficiaries": 35,
        "paying": 85
      }
    },
    {
      "id": 2,
      "name": "МАОУ Береговая СОШ",
      "report": null
    }
  ]
}
```

## Бесплатный хостинг и доступ по ссылке

### Почему не GitHub Pages

**GitHub Pages не может запустить это приложение.** Pages — это хостинг только статических файлов (HTML/CSS/JS). Ему недоступны Node.js, Express, сессии и SQLite, поэтому формы входа и отправки отчётов работать не будут.

Рабочая схема: **код хранится на GitHub, а приложение разворачивается на бесплатном Node.js-хостинге Render, который подключается к репозиторию GitHub.** В результате вы получаете обычную ссылку вида `https://zeya-nutrition-monitoring.onrender.com`, которой можно поделиться.

### Вариант 1. Render (рекомендуется)

1. Загрузите проект в GitHub (см. раздел выше).
2. Зарегистрируйтесь на <https://render.com> через GitHub.
3. В панели Render нажмите **New + → Blueprint**.
4. Выберите репозиторий с проектом. Render прочитает `render.yaml`.
5. Нажмите **Apply**. Render установит зависимости и запустит `npm start`.
6. После сборки получите ссылку на рабочее приложение.

Что уже настроено в `render.yaml`:

- бесплатный тариф;
- Node.js 24;
- `NODE_ENV=production`;
- часовой пояс `Asia/Yakutsk`;
- автоматически сгенерированный `SESSION_SECRET`;
- проверка доступности по адресу `/`.

Если Blueprint не сработал, создайте вручную **New + → Web Service** и укажите:

- Build Command: `npm install`
- Start Command: `npm start`
- Environment Variables:
  - `NODE_VERSION=24`
  - `NODE_ENV=production`
  - `APP_TIMEZONE=Asia/Yakutsk`
  - `SESSION_SECRET` — сгенерируйте случайное значение кнопкой Generate.

### Вариант 2. Свой сервер / VPS

Подойдёт любой хостинг с Node.js 24+ и постоянным диском (Timeweb, Beget, reg.ru и т.п.). Загрузите проект, выполните `npm install --omit=dev`, задайте переменные окружения и запустите процесс через PM2:

```bash
npm install -g pm2
pm2 start server.js --name zeya-nutrition
pm2 save
```

Для доступа по домену настройте reverse proxy Nginx и HTTPS-сертификат.

### Вариант 3. GitHub Codespaces (быстрая демонстрация)

Можно открыть репозиторий в GitHub Codespaces, выполнить `npm install && npm start` и сделать порт 3000 публичным. Ссылка будет временной, пока Codespace запущен. Это удобно для показа преподавателю, но не для постоянной работы.

### Ограничения бесплатного Render

- Бесплатный сервис засыпает после периода бездействия; первый запрос после сна загружается дольше.
- На бесплатном тарифе нет постоянного диска. Файл SQLite может быть потерян при перезапуске или повторной сборке сервиса.
- Для реальной эксплуатации нужен платный экземпляр с постоянным диском либо переход на PostgreSQL (например, Neon) с резервным копированием.

### «Доступ только по ссылке»

В проекте уже сделано:

- страницы и API закрыты от индексации (`noindex`, `robots.txt`, заголовок `X-Robots-Tag`);
- вход школ защищён логином и паролем.

При этом сам URL развёрнутого приложения технически публичен: «доступ по ссылке» не является полноценной защитой. Панель `/admin` по требованию задания открывается без пароля. Для реальной эксплуатации рекомендуется:

- добавить авторизацию для панели отдела образования;
- закрыть портал корпоративным VPN или reverse proxy с аутентификацией;
- сменить единый тестовый пароль;
- включить журналирование действий.

## Безопасность: что уже реализовано

- Пароли не хранятся в открытом виде: `scrypt` со случайной солью и сравнение через `timingSafeEqual`.
- SQL-запросы выполняются только через подготовленные выражения (защита от SQL-инъекций).
- Сессия пересоздаётся после успешного входа.
- Cookie: `HttpOnly`, `SameSite=Lax`, в production — `Secure`.
- Ограничение размера JSON-запроса.
- Content-Security-Policy запрещает inline-скрипты и inline-стили.
- Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Ограничение уникальности отчёта на уровне SQLite.
- Вывод названий учреждений на фронтенде через `textContent` (защита от XSS).

## Ограничения учебного прототипа

- Единый пароль для всех учреждений.
- Панель отдела образования без пароля — по требованию задания.
- Нет rate limiting для формы входа.
- Сессии хранятся в памяти процесса (MemoryStore): после перезапуска сервера нужно войти заново. Для production лучше подключить SQLite/Redis-хранилище сессий.
- Нет архива отчётов за прошлые даты в интерфейсе (API и схема базы к этому готовы: отчёты хранятся по датам).
