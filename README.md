# Мониторинг горячего и льготного питания

Веб-приложение для МКУ «Отдел образования администрации Зейского муниципального округа». Предназначено для ежедневного сбора и сводного мониторинга данных об организации горячего и льготного питания в подведомственных образовательных организациях.

Проект развит до учебной информационной системы: добавлены роли, управление пользователями, CRUD отчётов, поиск и фильтрация, экспорт в CSV, журнал действий, резервное копирование и проверка целостности базы данных.

Репозиторий: <https://github.com/m1fixqq/zeya-nutrition-monitoring>

## Возможности

- Личный кабинет образовательной организации с авторизацией по логину и паролю.
- Ежедневная форма из трёх числовых показателей: начальные классы с горячим питанием, льготники, плательщики.
- Блокировка повторной отправки отчёта за текущие сутки на уровне интерфейса и базы данных.
- Публичная сводная панель отдела образования за текущую дату без пароля.
- Сводная таблица по всем учреждениям района, подсветка не сдавших отчёт.
- Строка итогов по району, суммы рассчитываются на JavaScript.
- Административная панель с авторизацией:
  - список отчётов, поиск и фильтрация по датам, учреждению и тексту;
  - создание, редактирование и удаление отчётов;
  - выгрузка отчётов в CSV;
  - управление пользователями и ролями (`school`, `admin`);
  - включение и отключение учётных записей;
  - журнал действий пользователей;
  - резервное копирование базы данных;
  - проверка целостности базы данных.
- Строгий государственный дизайн: белый фон, тёмно-синяя шапка, прямые углы, крупная типографика без засечек.
- Адаптивная вёрстка для планшетов и телефонов.
- Разметка и стили по методологии БЭМ.

## Соглашение о вёрстке

Разметка и стили написаны по методологии **БЭМ**. Используется нотация `block__element_modifier`:

- блок — самостоятельный компонент: `header`, `form`, `report-table`, `admin-table`, `manage`;
- элемент — часть блока: `header__title`, `form__input`, `report-table__cell`, `manage__tab`;
- модификатор — вариант блока или элемента: `button_view_primary`, `status_value_ok`, `manage__tab_state_active`, `report-table__row_state_missing`.

CSS содержит только селекторы классов БЭМ. Утилитарных классов и стилизации по идентификаторам нет. JavaScript использует `id` для доступа к элементам, а состояния переключает через классы БЭМ.

## Быстрый запуск

```bash
cd zeya-nutrition-monitoring
npm install
npm start
```

В Windows можно дважды щёлкнуть `start.bat` — он установит зависимости при первом запуске и запустит сервер.

После запуска:

- личный кабинет организации — <http://localhost:3000>
- публичная сводная панель — <http://localhost:3000/admin>
- вход администратора — <http://localhost:3000/admin/login>
- управление системой — <http://localhost:3000/admin/manage>

Для разработки с автоматическим перезапуском:

```bash
npm run dev
```

Полностью пересоздать базу с тестовыми данными:

```bash
npm run db:reset
```

### Если `npm` не запускается в PowerShell

Используйте `npm.cmd`:

```powershell
npm.cmd install
npm.cmd start
```

Либо разрешите локальные скрипты:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

## Как пользоваться

### Представитель школы

1. Откройте <http://localhost:3000>.
2. Войдите под логином своего учреждения.
3. Заполните три поля за текущую дату.
4. Нажмите «Отправить отчёт за сегодня».
5. После успешной отправки появится подтверждение, а форма заблокируется до следующего дня. Повторная отправка за эту же дату невозможна.

Отчётная дата определяется на сервере по часовому поясу `Asia/Yakutsk` (UTC+9), чтобы даты не расходились на разных компьютерах.

### Сотрудник отдела образования

1. Откройте <http://localhost:3000/admin> — сводная ведомость доступна без пароля.
2. Для управления системой перейдите по ссылке «Вход для сотрудников».
3. Войдите как `admin` / `admin2026`.
4. В административной панели доступны разделы:
   - **Отчёты** — поиск, фильтрация, создание, изменение, удаление, выгрузка CSV;
   - **Пользователи** — создание, изменение, отключение и удаление учётных записей;
   - **Журнал действий** — входы, изменения отчётов и пользователей, экспорт, резервные копии;
   - **Резервное копирование** — скачивание копии и проверка целостности.

## Резервное копирование и восстановление

Скачать согласованную копию базы можно в разделе «Резервное копирование» или по адресу `/api/admin/backup` после входа администратора. Файл создаётся командой `VACUUM INTO`, поэтому не требует остановки сервера.

Восстановление выполняется при остановленном сервере:

```bash
npm run db:restore -- путь\к\файлу.db
```

Скрипт:

1. сохраняет текущую базу в файл `.before-restore-*`;
2. удаляет старые `-wal` и `-shm`;
3. копирует резервную копию;
4. выполняет `PRAGMA integrity_check` и `PRAGMA foreign_key_check`.

После успешной проверки запустите `npm start`.

## База данных

Файл базы: `data/nutrition.db` (путь можно изменить переменной `DB_PATH`).

### Таблица `schools`

Хранит и учреждения, и администраторов.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | Идентификатор пользователя |
| `name` | TEXT | Название учреждения или имя пользователя |
| `login` | TEXT UNIQUE | Логин |
| `password` | TEXT | Хеш пароля в формате `scrypt$соль$хеш` |
| `role` | TEXT | Роль: `school` или `admin` |
| `is_active` | INTEGER | Признак активной учётной записи |
| `created_at` | TEXT | Дата создания |

### Таблица `reports`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | Идентификатор записи |
| `school_id` | INTEGER FK | Ссылка на учреждение |
| `report_date` | TEXT | Дата отчёта в формате `YYYY-MM-DD` |
| `primary_hot_meals` | INTEGER | Начальные классы с горячим питанием |
| `beneficiaries` | INTEGER | Льготники |
| `paying` | INTEGER | Плательщики |
| `created_at` | TEXT | Дата создания |
| `updated_at` | TEXT | Дата последнего изменения |

Ограничение `UNIQUE (school_id, report_date)` не позволяет одному учреждению отправить два отчёта за одну дату.

### Таблица `audit_log`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | Идентификатор записи журнала |
| `user_id` | INTEGER | Идентификатор пользователя |
| `user_name` | TEXT | Имя пользователя на момент действия |
| `action` | TEXT | Код действия |
| `entity` | TEXT | Тип объекта |
| `entity_id` | INTEGER | Идентификатор объекта |
| `details` | TEXT | Подробности |
| `created_at` | TEXT | Дата и время |

### Индексы и представление

- `idx_reports_school_date` — ускоряет выборку отчётов по учреждению и дате.
- `idx_reports_date` — ускоряет сводку за дату.
- `idx_schools_role` — ускоряет выборку пользователей по роли.
- `idx_audit_created` — ускоряет журнал действий.
- `idx_audit_user` — ускоряет поиск по пользователю.
- `v_reports_full` — представление с названием учреждения, датой и показателями.

## Безопасность

- Пароли хранятся в виде `scrypt`-хеша со случайной солью, сравнение через `timingSafeEqual`.
- SQL-запросы выполняются через подготовленные выражения.
- Сессия пересоздаётся после успешного входа.
- Cookie: `HttpOnly`, `SameSite=Lax`, в production — `Secure`.
- Ограничение размера JSON-запроса.
- Content-Security-Policy запрещает inline-скрипты и inline-стили.
- Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Ограничение попыток входа: 10 неудачных попыток за 15 минут.
- Проверка ролей на каждом административном маршруте.
- Запрет удаления собственной учётной записи и последнего администратора.
- Запрет удаления пользователя, у которого есть отчёты.
- Журналирование входов, изменений и выгрузок.

## Ограничения учебного прототипа

- Единый пароль для всех тестовых учреждений.
- Публичная сводная панель `/admin` открывается без пароля по исходному ТЗ.
- Сессии хранятся в памяти процесса (MemoryStore): после перезапуска сервера нужно войти заново.
- SQLite подходит для небольшой нагрузки отдела образования; для промышленной эксплуатации рекомендуется PostgreSQL и постоянное дисковое хранилище.
- Нет постраничного вывода журнала и отчётов; установлен лимит 200 записей журнала.
- Нет загрузки резервной копии через браузер: восстановление выполняется скриптом при остановленном сервере.

## Публикация и хостинг

Код хранится на GitHub. Для постоянного размещения подходит Render:

1. Загрузите проект в GitHub.
2. В Render создайте **New → Web Service** и подключите репозиторий.
3. Укажите:
   - Build Command: `npm install`
   - Start Command: `npm start`
   - `NODE_VERSION=24`
   - `NODE_ENV=production`
   - `APP_TIMEZONE=Asia/Yakutsk`
   - `SESSION_SECRET` — случайное значение.
4. Выберите бесплатный тариф.

Файл `render.yaml` уже содержит эти параметры. Для бесплатного тарифа Render может потребовать привязку карты для проверки (обычно $1 без списания). На бесплатном тарифе нет постоянного диска, поэтому база SQLite может сбрасываться при перезапуске сервиса.

GitHub Pages не подходит: он не запускает Node.js, Express, сессии и SQLite.
